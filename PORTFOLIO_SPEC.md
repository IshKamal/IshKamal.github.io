## **6\. Visual Direction**

### **Overall Feel**

Create a clean, modern analytics portfolio: confident, precise, calm, and evidence-led. It should feel more like a polished editorial data story than a generic developer template.

### **Color**

Use a restrained palette with strong contrast:

* Warm white or very light neutral background.  
* Deep navy or charcoal for primary text.  
* One primary accent such as teal, blue, or blue-green.  
* One secondary accent used sparingly for chart or project differentiation.  
* Muted neutral borders and card backgrounds.

Define colors as CSS custom properties. Verify normal text and interactive states meet WCAG AA contrast requirements. Do not rely on color alone to convey meaning.

### **Typography**

* Use a highly readable sans-serif for body copy and navigation.  
* A complementary display face may be used for headings, but limit the site to two font families.  
* Prefer a system-font stack or locally hosted/openly licensed font files. The site must remain usable if web fonts fail.  
* Use a clear type scale with comfortable line length and generous spacing.  
* Avoid tiny labels, dense walls of text, and all-caps paragraphs.

### **Layout**

* Use a centered content container with a comfortable maximum width.  
* Use responsive grids that collapse cleanly to one column.  
* Give featured project imagery enough size to be legible.  
* Keep alignment, spacing, corner radii, and shadows consistent.  
* Use whitespace to separate sections rather than excessive decorative dividers.

### **Data-Portfolio Motifs**

Subtle visual motifs may include grid lines, compact metric cards, chart-inspired accents, or small data labels. These are decorative and must not present fabricated data. Every actual chart must use verified project data and have a title, labels, units, legend when needed, and a short interpretation.

### **Motion**

* Use limited, subtle transitions for hover, focus, navigation, and section reveal.  
* Respect `prefers-reduced-motion` and disable nonessential motion when requested.  
* Do not use parallax, autoplay video, looping background animation, or effects that delay access to content.

## **12\. Accessibility Requirements**

Meet WCAG 2.2 AA as the target standard.

* Use semantic HTML landmarks: `header`, `nav`, `main`, `section`, `article`, and `footer`.  
* Use one `h1` per page and a logical heading hierarchy.  
* Provide a visible `Skip to main content` link.  
* Ensure every interactive element is usable by keyboard.  
* Use obvious, consistent focus indicators that are not removed by CSS.  
* Ensure touch targets are comfortably sized.  
* Associate form labels with controls if a form is added.  
* Provide meaningful link text; avoid repeated `click here` links.  
* Provide alt text according to the image rules above.  
* Ensure charts do not rely on color alone and include a text summary or accessible table where appropriate.  
* Respect reduced-motion and user color-scheme preferences if dark mode is implemented.  
* Test at 200% browser zoom without lost content or functionality.  
* Do not create horizontal page scrolling at common mobile widths.

* Add appropriate `aria-current` state to current navigation links.

### **CSS**

* Organize reusable colors, spacing, typography, widths, radii, and shadows as custom properties.  
* Use Grid and Flexbox for layout.  
* Avoid large third-party CSS libraries.  
* Keep specificity controlled and component naming understandable.  
* Include print styles so the page remains clean when printed or saved as PDF.

### **JavaScript**

* Keep JavaScript small, dependency-free, and deferred.  
* Do not hide essential content behind scripts.  
* Avoid scroll hijacking.  
* Ensure menu state and dialogs have correct keyboard and ARIA behavior.  
* Do not add analytics, trackers, cookies, or third-party embeds without Ishmam's approval.

* Target strong Lighthouse results, with 90+ as a practical goal in Performance, Accessibility, Best Practices, and SEO.  
* Keep the initial page lightweight.  
* Optimize and size images appropriately.  
* Avoid render-blocking third-party scripts.  
* Preload only truly critical assets.  
* Prevent cumulative layout shift by reserving media dimensions.

### **SEO and Sharing**

* Use descriptive titles and metadata, not keyword stuffing.  
* Add a small `sitemap.xml` and `robots.txt` once the production URL is known.  
* Add Person and/or ProfilePage structured data only with verified details and valid URLs.
